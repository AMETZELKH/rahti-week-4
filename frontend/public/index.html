Documentation

Application

This application is a simple visitor counter running on Rahti. The frontend communicates with a backend REST API, and the backend reads and writes data in a MySQL database.

Frontend - Backend - Database

The frontend communicates with the backend through the backend Service. The backend queries and updates the MySQL database. This is demonstrated by the page view counter: clicking “Count visits” changes the value stored in MySQL and the updated value is displayed by the frontend.

Database persistence

The MySQL Pod was deleted and automatically recreated by the Deployment. The page view counter retained its previous value, demonstrating that the database data is stored on persistent storage rather than only inside the Pod.

Pod recovery

A backend Pod was manually deleted. The Deployment automatically created a replacement Pod. After the replacement became Ready, the application continued to work normally.

Scaling

The backend Deployment was scaled from 1 replica to 3 replicas using oc scale. Kubernetes created two additional backend Pods. The frontend continued to access the backend through the Service, so it did not need to know the individual Pod addresses.

Docker Compose vs Rahti

With Docker Compose, the three containers were defined and managed together on a single Docker host. Networking was created through the Compose network and persistent storage was attached directly to the database container.

In Rahti, the application is split into Kubernetes Deployments and Services. Services provide stable internal DNS names such as backend and db, while Pods can be recreated or scaled independently. The frontend is exposed externally through an OpenShift Route. Database storage is provided through a PersistentVolumeClaim, and configuration and credentials are managed separately using ConfigMaps and Secrets.

SO the main change is not simply the configuration-file format. Rahti changes how the application is deployed and managed. Kubernetes continuously manages the desired number of Pods, provides service discovery, supports scaling and automatic Pod recovery, and separates persistent storage and configuration from individual containers.
